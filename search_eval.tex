\title{Cost of the Certified Action Search:\\
Evaluation of Search Optimisations by Depth}
\author{} % add author
\date{27 October 2026}

\begin{document}
\maketitle

\begin{abstract}
The action masker certifies an action only if some action sequence starting
with it satisfies the manoeuvre specification against the obstacle's
reachable tube. This report measures what an exhaustive search for such
sequences costs as a function of search depth, and compares five
implementations of the pacSTL predicate evaluation that the search relies on.
On ten detection states of a give-way crossing, an exhaustive depth-10 search
(400~s lookahead, 2.3 million projected nodes) takes 77.3~min on one core with
the production code. Sharing geometry between predicates brings this to
47.7~min ($1.62\times$), solving the secular equations in compiled code to
36.6~min ($2.11\times$), and pruning on the turn rule is estimated to bring it
to 27.3~min ($2.83\times$). Both implemented optimisations give the same
certified sequences as production. The tree grows by a factor of about $4.8$
per level, so these constant-factor gains amount to about two thirds of one
depth level. After the optimisations, the ego projection is the largest
remaining cost (47\% of the time per node).
\end{abstract}

\section{Purpose}
%======================================================================

During training and deployment, the action masker allows an action only if
it can find a sequence of actions, starting with that action, whose projected
trajectory satisfies the manoeuvre specification for every obstacle state in
the reachable tube. The deeper the search, the further ahead the certificate
reaches, but the number of sequences grows exponentially with depth. The
evaluation answers three questions:
\begin{enumerate}
  \item How long does an exhaustive search take for each depth?
  \item Where is that time spent within one node of the search tree?
  \item How much do the optimisations of the predicate evaluation save, and
        do they change which sequences are certified?
\end{enumerate}

%======================================================================
\section{The search problem}
%======================================================================

\subsection{Search tree}

The ego chooses among five yaw-rate commands,
$\dot\psi_{\mathrm{cmd}} \in \{-1, -0.5, 0, 0.5, 1\}~^\circ/\mathrm{s}$, each
held for $\Delta t = 40$~s. A sequence of $d$ actions therefore looks
$40d$~s ahead, and there are $5^d$ sequences of depth $d$. Two hard action
constraints are checked before an action is projected: the crossing-side rule,
which keeps the commanded heading offset from the original course at or above
zero (no net turn to port in a crossing), and a speed floor (which never binds
here, since the actions do not change speed). Sequences that violate them are
never projected.

Every edge of the tree is one \emph{rollout}: the Mariner hull and autopilot
are simulated in closed loop for 40~s ($800$ integration steps of 0.05~s)
from the parent's state. The node that the rollout reaches is then evaluated
against the obstacle's reachable set at that time step.

\subsection{Specification}

The run uses the manoeuvre specification
\code{maneuver\_verified\_LOS\_turn}. For a trace of $d$ samples (indices
$0,\dots,d-1$) it reads
\begin{align}
  \varphi_d \;=\;& \square\,(\mathrm{occupancy\_clear} \ge 0) \nonumber\\
  \wedge\;& \lozenge_{[d-2,\,d-1]}\,(\mathrm{collision\_possible\_LOS} \le 0)
  \label{eq:spec}\\
  \wedge\;& \square\,\big((\mathrm{course\_alteration} \ge 0) \vee
            (\mathrm{range\_closing} \le 0) \vee
            (\mathrm{target\_starboard} \le 0)\big). \nonumber
\end{align}
The first conjunct keeps the safety radius (482.8~m, three ship lengths) at
every sample. The second requires the line-of-sight collision risk (time
horizon $t_h = 300$~s) to be resolved at one of the last two samples; this is
the window the receding search uses at each depth. The third is the turn
rule: a starboard course offset that follows the range (up to
$\theta_{\max} = 20^\circ$, scheduled from $t_{\mathrm{start}} = 480$~s of
closing), excused once the range is certainly opening or the target is
certainly not to starboard.

Each predicate is evaluated with interval semantics over the reachable set:
it returns a lower and an upper bound over all obstacle states in the set. A
sequence is \emph{certified} at depth $d$ if the lower robustness bound of
$\varphi_d$ is at least the certification margin, here $0$.

\subsection{Predicates as optimisation problems}

The obstacle's reachable set at a time step is an ellipsoid
$\mathcal{E} = \{p : \lVert A p - b \rVert \le 1\}$ in its 6-D state. A
predicate bound is the minimum or maximum of a function over this set:
\begin{itemize}
  \item the minimum and maximum ego--obstacle distance (occupancy, line-of-sight
        collision risk, range closing, course alteration);
  \item the maximum relative speed (line-of-sight collision risk);
  \item bounds on the closing rate $-\Delta p^{\top}\Delta v$ (line-of-sight
        collision risk, range closing);
  \item linear bounds, such as the target's bearing relative to the ego's
        original course (target to starboard) and the obstacle speed bounds of
        the course-alteration schedule.
\end{itemize}
The quadratic problems are posed on the projection of $\mathcal{E}$ onto two
dimensions (position or velocity), and are the expensive part. Section~\ref{sec:methods}
describes how each implementation solves them.

\subsection{Incremental evaluation}

A predicate sample depends only on the ego state at its time step and the
reachable set of that time step. It does not depend on later samples or on
the window of the specification. Each node therefore computes one new sample
and copies the samples of its ancestors (Figure~\ref{fig:tree}). The STL
formula is evaluated once per leaf, over the full trace of that leaf.

roughly eight times fewer predicate evaluations, with identical values.

the first ten. Loading the tube happens once per encounter, before the search,
and is not part of the search time.

\subsection{Time accounting}

The tree to depth 10 is searched once per state and method. Every node is
timed, and its time is added to the bucket of its depth. The time of an
exhaustive depth-$d$ search is then
\begin{equation}
  T(d) \;=\; \sum_{k=1}^{d} t_{\mathrm{node}}(k) \;-\; \sum_{k=1}^{d-1} t_{\varphi}(k),
  \label{eq:time}
\end{equation}
where $t_{\mathrm{node}}(k)$ is the total time of the nodes at depth $k$
(projection, predicates, formula, bookkeeping) and $t_{\varphi}(k)$ is their
formula time. The evaluation needs the formula at every node to count the
certified sequences of each depth, but a depth-$d$ search only evaluates it at
its leaves; the second sum removes that extra work. The projection and
predicates of the inner nodes stay in, since a depth-$d$ search needs them to
build its leaf traces. Leaving out the inner formula evaluations lowered the
depth-10 time by 2.7\% (production) to 5.1\% (compiled roots).

All times are one-core times (summed over worker processes) and are reported
as the median over the ten states. With \code{--profile-parts}, timers split
each node's time into projection, root finding, other predicate work, formula
and other; their overhead is the same for every method.

\section{Methods}
\label{sec:methods}
%======================================================================

The tree, the states and the specification are identical for all methods.
The methods differ only in how a node's predicates are computed; pruning also
changes which nodes are visited. The optimised methods are implemented as
\emph{variants}: modules that replace production functions at run time, so
the production code is not edited (\code{gym/eval/search/variants/}).
Table~\ref{tab:methods} gives an overview.

\subsection{Production}

\paragraph{Minimum distance.}
Let the projection of $\mathcal{E}$ onto the two dimensions of interest be
$\{x : (x-c)^{\top}\Sigma^{-1}(x-c) \le 1\}$ with
$\Sigma = U\Lambda U^{\top}$, $\Lambda = \mathrm{diag}(\lambda_1,\lambda_2)$.
The minimum of $\lVert x - x_o\rVert^2$ over this set, for a point $x_o$ such as
the ego position, follows from the Lagrange conditions. With
$\delta = U^{\top}(x_o - c)$, the minimum is $0$ if
$\sum_i \delta_i^2/\lambda_i \le 1$ (the point lies inside). Otherwise
\begin{equation}
  \min \lVert x - x_o\rVert^2 = \sum_i \left(\frac{\mu\,\delta_i}{\lambda_i+\mu}\right)^{2},
  \qquad
  \text{where } \mu > 0 \text{ solves } \;
  \sum_i \frac{\lambda_i\,\delta_i^2}{(\lambda_i+\mu)^2} = 1 .
  \label{eq:secular-min}
\end{equation}
The left-hand side of the \emph{secular equation} is strictly decreasing in
$\mu$, so it has one root in $[0, \sqrt{\textstyle\sum_i \lambda_i\delta_i^2}]$,
found with Brent's method.

\paragraph{Maximum distance.}
Similarly, with $\delta = U^{\top}(c - x_o)$, the maximiser is
$v = U\,\mathrm{diag}\!\big(\gamma/(\gamma-\lambda_i)\big)\,\delta$, where
$\gamma > \lambda_{\max}$ solves
$\sum_i \lambda_i\delta_i^2/(\gamma-\lambda_i)^2 = 1$.

\paragraph{Linear bounds.}
A linear function $a^{\top}p - \beta$ over $\mathcal{E}$ ranges over
$a^{\top}c - \beta \pm \lVert A^{-\top}a\rVert$, with $c = A^{-1}b$. These are
evaluated in closed form.

\paragraph{Caching.}
$A^{-1}$, the centre and the eigen-decomposition of each projection are cached
per reachable set. The secular equation itself is a Python function, so each
iteration of \code{brentq} (about ten per root) calls back into the
interpreter. Each predicate solves its own problems, even when another
predicate of the same sample has already solved the same one.

\subsection{Shared geometry}

Within one sample, several predicates pose the same problem: the turn
specification asks for the same minimum and maximum ego--obstacle distance in
four predicates (8 root solves for 2 distinct ones), and the closing-rate
bounds are needed by both the line-of-sight rule and range closing. The
variant memoises \code{min\_quadratic\_projected},
\code{max\_quadratic\_predicates} and the closing-rate bounds for the duration
of one sample, keyed by reachable set, dimensions and ego values, so each
distinct problem is solved once. The ego-independent part of the
closing-rate bound (a transform and the eigenvalues of its quadratic term) is
cached per reachable set. The solver and its inputs are unchanged, so the
results are bit-identical.

\subsection{Compiled roots}

The secular equations are solved in numba-compiled code. Both have the form
$F(x) = \sum_i w_i/(x \pm \lambda_i)^2 = 1$ with $F$ decreasing on the
bracket. Near a pole $F \approx w/s^2$, which makes plain Newton on $F - 1$
take steps of about $s/2$ and stop early. The variant therefore applies
Newton to $\psi(x) = F(x)^{-1/2} - 1$, which is close to linear there (the
usual trust-region form), keeps the bracket updated, and falls back to
bisection whenever a step leaves it. The tolerances match production's
\code{brentq} calls. The results are not bit-identical but agree within the
tolerances (Section~\ref{sec:verification}). In this evaluation it is applied
on top of shared geometry.

\subsection{Pruning on the turn rule (estimate)}

The turn conjunct is an \emph{always}: once its lower bound at one sample is
below the margin,
\begin{equation}
  \max\!\big(\underline{\mathrm{course}},\; -\overline{\mathrm{closing}},\;
  -\overline{\mathrm{starboard}}\big) < 0,
\end{equation}
no extension of the sequence can be certified. A search could stop expanding
such a node. The check reads only the newest sample and costs almost nothing.
Pruning was not run; the evaluation counts the rollouts below such nodes
(\code{prunable\_rollouts}) and scales the time by the share of rollouts that
would be kept. It also counts certified sequences that pass through a failed
prefix; this count is $0$, which confirms that the check matches the
specification.

\subsection{Legacy implementations}

\paragraph{Legacy optimiser.} Before 26 September 2026 the minimum distance,
the minimum relative speed and the linear bounds were solved numerically with
SLSQP over the full 6-D ellipsoid, started at the centre. SLSQP is a local
solver: the minimum it returns can be too large, which makes a lower bound
too high (unsafe for certification).

\paragraph{Legacy full trace.} Before the same change, every node evaluated
the specification over the whole trajectory, recomputing every sample of the
sequence instead of reusing its parent's. The values are the same; only the
work differs. The predicates added since (range closing, target to starboard,
course alteration) run on top of both legacy variants.

\section{Verification}
\label{sec:verification}
%======================================================================

Two checks establish that an optimisation does not change the certificates.

\paragraph{Whole search.} The counts of every depth (rollouts, clear,
certified and extendable sequences) are compared state by state with
production. They are identical for shared geometry and for shared geometry
with compiled roots. They are also identical to the previous run of
21 October, which shows that the per-depth formula timer did not change the
search. The legacy optimiser certifies 10 more sequences at depth 7, in 4 of
the 10 states.

\paragraph{Predicate inputs.} \code{variant\_check} records a random sample of
predicate inputs (reachable set, projected ego state, time step) from the
production search and evaluates each with production and with the variant

certify a sequence that production does not.

By depth 10 the hard action constraints have removed about three quarters
of the sequences (Table~\ref{tab:certified}), mostly through the first
levels, where only 3 of the 5 actions are allowed. From depth 5 on, each
level multiplies the projected sequences by about $4.8$ (against $5$ without
constraints). No projected node violates the safety radius within 400~s in
any state: the obstacle is 6--10~km away at detection. Nothing is cut below
the hard constraints, and the tree has the same 2\,954\,861 nodes up to
depth 10 in every state, of which 79\% are leaves. Every inner node's sample
is therefore used by at least one leaf; no predicate solve is wasted on a
dead branch.

Between 17\% and 40\% of the sequences of each depth are certified, with the
share falling with depth (Figure~\ref{fig:certified}). About 25\% of the
rollouts to depth 10 lie below a sequence whose turn rule has already failed.
These rollouts are spent on leaves whose outcome is already known, which is
the saving the pruning estimate counts.

%======================================================================
\section{Discussion}
%======================================================================

\paragraph{What the speed-ups buy.} Since the tree grows by a factor of about
$4.8$ per level, a constant speed-up $s$ is worth $\ln s/\ln 4.8$ levels:
$2.83\times$ corresponds to about $0.66$ of a level, or about 26~s of
lookahead. With a 10-minute one-core budget, production reaches depth 8
(3.4~min, depth 9 takes 16.1~min); the optimised search with pruning reaches
depth 9 (5.7~min). An exhaustive search to depth 10 remains out of reach
online, so deeper certificates need fewer branching levels (for example
longer action holds at later levels), not only faster nodes.

\paragraph{Where to optimise next.} After the two predicate optimisations,
47\% of the node time is the ego projection, a 40-s closed-loop simulation of
hull and autopilot. Pruning on the turn rule is the cheapest remaining gain
(an estimated $1.34\times$ with identical certificates). Beyond that, the
formula could be monitored incrementally instead of evaluated over the whole
trace at each leaf, and subtrees could be searched in parallel; the
evaluation itself uses 40 processes and finishes the production depth-10 runs
of all ten states in 27.5~min.

\paragraph{Limitations.}
\begin{itemize}
  \item The exhaustive tree is the cost of the phased plan, which builds the
        full tree. The receding mask searches depth first and stops at the
        first certified leaf for each first action, so it is usually much
        cheaper. The times here are an upper bound for it.
  \item Only the detection state of a give-way crossing was evaluated. Later
        decisions, closer to the obstacle, would cut branches on the safety
        radius and give smaller trees.
  \item There is no ego-uncertainty budget in this configuration. The widened
        predicates cost about the same, so the timings should carry over.
  \item The pruning result is an estimate. It assumes that a pruned rollout
        costs as much as an average one.
  \item Each state and method was searched once, so run-to-run variation is not
        measured separately. The ten states agree within $\pm 3\%$, and all
        methods ran one after another on the same node.
\end{itemize}

%======================================================================
\section{Conclusion}
%======================================================================

An exhaustive certified search to depth 10 (400~s lookahead, 2.3 million
rollouts per state) costs 77~min on one core with the production code.
Sharing geometry between predicates and solving the secular equations in
compiled code reduce this to 37~min ($2.11\times$) without changing a single
certified sequence, and pruning on the turn rule is estimated to reach 27~min
($2.83\times$). The legacy SLSQP optimiser was $87\times$ slower than
production and could raise lower bounds, which makes it unsafe for
certification. Because the tree grows by about $4.8\times$ per level, these
gains are worth less than one level of depth. The remaining cost is
dominated by the ego projection.
